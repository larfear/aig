# AIG 内容接入与公网交付契约草案

版本为 `0.1-draft`。AIG 以网关为核心，存储可选；契约说明内容如何取得和由谁提供公网访问，不能仅以“已有文件”推定外部可读。当前提供文件源和 D1 实现，支持通用发布者及显式运行模式。接入操作见[发布者说明](publisher-integration.md)。

本契约是随参考实现提供的项目约定。它复用 HTTP 和 JSON Feed；当前不宣称为普遍标准，也不要求客户端自动发现入口。后续是否演进为更普遍的协议，依据实际需求和多方接入实践决定。

## 场景与部署责任

| 场景 | 接入方 | 存储方 | 公网提供方 |
| --- | --- | --- | --- |
| S1 平台内直接发布 | 平台运营方，或基于足够授权接口的适配方 | 原平台 | 平台或其授权适配的公网运营方 |
| S2 自有工具且已有线上源 | 发布者或工具/站点维护者 | 既有源运营方 | 发布者或其选定线上运营方 |
| S3 自有工具且仅本地源 | 发布者或工具维护者 | 原本地源，或选用的在线副本存储方 | 保持源可达的公网网关运营方，或在线存储与网关托管方 |

完整责任划分见 [项目方案](project-plan.md)。S3 可由可达网关直接服务原本地源，或同步公开内容到选定在线存储；本地设备离线后仍可读需要持续在线承载。可选 AIG 存储模块可由发布者或其选定托管方运行，不要求集中式平台。

第一版只围绕可控发布工具，不假设第三方平台支持 AIG。平台发布成功、公开页面存在与 AIG 入口可读是不同结果。

S3b 使用托管附加模块：本地发布工具主动同步选定公开内容，线上托管和网关持续提供读取，不开放本地源。托管对 Core 可选，采用 S3b 时需要完整同步链路，见[托管附加功能](hosting-addon.md)。

## 发布工具与源适配

发布工具维护一份最终正文、ID、版本、状态及公开时间，写入或更新其内容源。源适配器提供列举资源与按 ID 读取能力；AIG Core 不依赖工具内部业务模型或平台接口。

默认复用已有内容源，不要求额外提交正文副本。选择在线副本时，发布工具负责同步该版本及更新/撤回；存储运营方负责持久保存。复制成功不替代客户端经公网读取成功。

首版本地演示工具直接维护合成文件源，网关只读。演示工具只是可控的发布端，不扩展为完整 CMS 或多平台分发系统。

核心链路通过后，演示工具继续验证 S3b 同步。托管模块接受带发布凭据的新增、更新和撤回，完整保存后按统一契约返回。相同版本同内容幂等，不同内容冲突明确拒绝，失败不宣称新版本已公开。

公共读取路由与发布/撤回路由分开：已发布正文可匿名读取，写入和撤回必须校验发布凭据及服务端绑定的操作范围；配置管理不提供公开入口，不依赖源 URL 或资源 ID 难猜来授权。

托管写入固定为 `PUT /publish/items/{id}.json`，Content-Type 为 application/json，凭据放在 `Authorization: Bearer ...`。正文沿用资源 Schema，status 为 published 或 withdrawn；不使用无版本的 DELETE。路径 ID 与正文 ID 必须一致，发布者 ID 必须与服务端凭据范围一致，已有资源不允许更换所有者。

首个版本须为 published、revision 1。后续提交使用连续版本，保持首次公开时间、发布者 ID、source.system 和 source.record_id，updated_at 不早于上一版。相同版本的规范化 JSON 相同才视为幂等，键顺序可不同，正文空白不可改变。D1 保留私有版本记录，已知旧版本重试不回退当前状态；文件演示工具只识别当前版本的幂等，过时提交返回冲突。

成功回执含 id、revision、outcome（stored 或 unchanged）、current_revision 和 current_status。D1 的版本保存和当前指针更新在同一事务内完成；同版本不同内容、跳号和身份变化返回 409，未授权返回 401、越权返回 403。保存失败返回 503，不能当作同步成功；回执仍不替代实际读取核对。

## 源访问与公网访问

| 连接 | 要求 |
| --- | --- |
| 发布工具到源 | 发布动作完成后可取得确定的最终正文、版本和状态 |
| 源到网关 | 源适配器具备明确授权和可达路径，返回完整对应版本 |
| 网关到客户端 | 指定公网运营方提供实际可访问的统一入口 |
| 可选在线副本 | 存储和同步责任明确，失败不宣称新版本已对外可读 |

源无需直接将数据库或文件系统暴露到公网，客户端经网关访问即可；但网关必须能取得源内容。仅 localhost 的源适配通过属于本地验证，不算公网交付。

## 读取入口

| 入口 | 用途 |
| --- | --- |
| `GET /items/{id}.json` | 从源取得完整资源 |
| `GET /manifest.json` | 描述实际可用能力和地址 |
| `GET /feed.json` | 根据源目录生成当前内容 Feed |
| 人读页面、HEAD、ETag、healthz | 后续按需要增加 |
| 增量、订阅、MCP | 后续扩展 |

源缺失、读取失败、格式错误或超限要明确报告，不伪装为成功或空正文。manifest 只能宣告已实现能力，样例地址不代表已部署入口。

## 资源封装与完整性

[resource.schema.json](../schemas/resource.schema.json) 规定客户端取得的资源结构，不规定具体存储和部署。现有草案 Schema 不因三场景划分而改变。

| 字段 | 草案语义 |
| --- | --- |
| `schema_version` | 对外交付封装版本 |
| `id` | 源适配映射的稳定资源 ID |
| `publisher` | 发布者标识和名称 |
| `source` | 公开来源键及可选公开地址，不含私有连接配置 |
| `revision` | 对应源版本 |
| `status` | published 或 withdrawn |
| `published_at` / `updated_at` | 源提供的首次公开和版本更新时间 |
| `synthetic` | 合成内容标记 |
| `representations` | 完整正文或内容文件地址 |
| `extensions` | 可忽略的发布者扩展 |

一次读取返回同一版本的内容与元数据。JSON 包装可转义字符，但解码后须与发布工具的最终正文一致，保留空白、中文、换行和符号，不改写或截断。标注公开时间本身不证明公网已经可达。

源更新后同一地址提供对应新版本；撤回或移除时不继续返回旧正文。在线副本启用后，其更新和撤回也须同步；默认无副本模式不保证源离线期间可读。

撤回详情返回 410 和满足资源 Schema 的最小墓碑：身份、来源、版本、时间、状态、撤回原因与空 representations；不返回标题、扩展或旧正文。Feed 移除撤回条目，公开路由不支持历史版本读取，响应使用 no-store。D1 内部历史保留用于幂等，不代表物理删除或撤销消费者已取得的副本。

已发布资源必须至少有一份 original 的 text/plain 或 text/markdown 内联正文。Feed 的 content_text 原样复制首份主文本，全部表示列表及来源在 _aig 中保留；详情保留完整资源。URL 表示不会被自动抓取，纯 URL 或二进制发布暂不支持。单次提交/资源上限 256 KiB、响应上限 2 MiB；文件源最多 100 个当前资源，D1 Feed 最多 100 个已发布资源，超限明确失败，不静默截断，分页待后续需要。

服务端 `AIG_CONTENT_MODE` 默认为 synthetic，只允许合成资源；显式 public 模式允许真实和合成资源。manifest.synthetic 与 Feed._aig.synthetic 标识服务是否限合成，Feed item._aig.synthetic 与详情 synthetic 标识该条资源；public 不会把合成内容改标成真实。同一 ID 的 synthetic 随身份固定，不能通过更新切换。模式配置无效时明确 503，synthetic 服务遇到非合成写入为 422，读取到非合成源为 503；不静默放行或过滤。真实发布者仍必须使用服务端已配置的独立凭据和相同的 scope、版本、完整性规则。

Feed 格式参考 [JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)，`_aig` 扩展提供资源地址和版本。静态样例只用于检查格式，不能替代实际发布工具与读取链路。

## 必要安全

只读取显式配置并允许公开的资源，外部请求不任意指定路径或上游地址。S3b 公网使用 HTTPS，发布凭据仅放授权请求头；写入及撤回校验操作范围，失败尝试和高频请求限速，大小超限明确拒绝。后端存储不开放匿名列举或直接访问，公开客户端仅经网关取得已发布资源。日志与错误不泄露凭据或内部路径。

以上随功能实现，只覆盖必要防护，不提前建设复杂权限、签名、多层审核或内容审查。防护详见 [托管附加功能](hosting-addon.md)。

AIG 不评价事实或消费者理解，不产生摘要或替换原文。本地测试、实际发布者调用、公网可达性与采用情况分别验收，见[验证说明](verification.md)。
