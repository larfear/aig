# 功能与公网交付验收

验收对象是内容交付：同一正文、来源、身份、版本、更新和撤回。AIG 不评估事实正确性或消费者理解质量，也不以陌生智能体自动发现或采用作为本地功能完成条件。

## 本地链路

```sh
npm ci
npm run verify
```

以两个通用合成发布者覆盖文件源和可选 D1，同一核心不出现发布者专用业务分支。检查实际发布动作到 HTTP 客户端的读取，不能只校验静态样例。

| 行为 | 通过条件 |
| --- | --- |
| 完整读取 | 解码后正文与最终快照逐字一致，保留中文、空白、换行、emoji、来源、ID 和版本 |
| 更新 | 同地址返回新的连续版本与正文，Feed 相应更新 |
| 幂等 | 精确重试无重复状态变更，冲突与跳号明确拒绝 |
| 持久化 | 本地 D1 服务重启后同一版本仍可读 |
| 撤回 | 详情 410、无正文，Feed 移除，旧请求不恢复内容 |
| 必要失败 | 错误凭据、越权、坏格式、大小超限和源失败明确报错，不静默截断 |

`acceptance:local` 用独立发布 CLI 与匿名读取 CLI 验证五个生命周期节点。发布者适配器仍需由自己的代码实际发起同样请求；AIG 自验不替代适配验收。

## 公网与托管

运营者明确谁接入、存储位置、网关地址、源可达路径及更新/撤回责任。S3b 同步公开副本，不让公网回连本地文件。

按[受控验收](controlled-launch-plan.md)分别检查真实 HTTPS、持久化、独立网络、发布机离线、版本、撤回、权限及收尾。指定入口一次成功不能推定全球可达；边缘节点位置不能代替客户端位置。

## 可选采用观察

其他客户端成功读到原文是交付证据；自动发现、持续使用、需求规模和协议推广是另外的观察。没有自然访问不否定已完成的交付功能，有访问量也不证明消费者正确理解。

## 记录格式

```text
源码/运行版本与日期：
场景（准备、本地、指定公网、独立网络或采用）：
接入工具与身份范围：
内容存储与公网提供方：
实际发起的操作、回执与精确读取结果：
更新、撤回、失败及重试：
未执行项与限制：
```

运行资料放在忽略目录，公开报告只保留必要状态与合成复现，不上传凭据、私人路径或未审核正文。各类证据边界见[验证说明](verification.md)。
