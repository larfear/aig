# 检查与证据边界

## 复现命令

```sh
npm ci
npm run verify
```

`verify` 在本地运行，不登录云账号、写入远端、调用模型或发送 X。生成报告位于忽略的 `.local/`。所有正文均为人工构造，公开样例与一键联调保持 synthetic:true；少量 synthetic:false 夹具只测试显式 public 分支。

| 检查 | 实际范围 |
| --- | --- |
| `doctor` | Node/npm/Git/OpenSSL 和已安装依赖版本 |
| `typecheck` | 生成严格 Ajv 校验器、Node 与 Worker 类型检查 |
| `validate:examples` | 3 份 Schema、6 份合成样例及跨文件一致性 |
| `check:local` | 本地环境 Worker 和模拟 D1 探针 |
| `test` | 文件/D1 HTTP 功能、权限、幂等、冲突、模式、重启、撤回、TLS 与部署配置 |
| `acceptance:local` | 独立发布/读取 CLI 的发布、更新、重启、撤回、旧请求五个读取检查点 |

测试使用回环 HTTPS 和临时 CA，证书校验保持启用；临时数据库、证书和密钥在结束后清理。异常中断时应核对残留进程与忽略目录。

## 2026-10-21 公开准备回归

在 Node 24.14.0 / npm 11.9.0 的 macOS 环境执行完整 `npm run verify`，类型检查、6 份样例、环境探针、28 项测试（无跳过/失败）与五个生命周期读取节点通过。临时服务已停止，本轮运行数据库和密钥已清理。

此结果来自本地合成测试，不代替云端压力、独立网络或真实稿件一致性验证。GitHub CI 的结果在仓库 Actions 中单独记录。

## 单独验收发布者

`npm run acceptance:read -- --expect <文件>` 只读取选定资源，不需要 token，比较完整正文、来源、ID、版本、模式、Feed、墓碑和 no-store。非回环需显式 `--target` 允许的唯一 HTTPS origin。

期望必须来自发布者最终公开快照。客户端读回自身构造的新摘要不能证明逐字交付。通用自验不替代发布者适配器实际发起请求的证据。

## 公开入口

维护者实例的[2026-10-21 记录](production-launch-20261021.md)区分已有上线验收与本次匿名只读检查。仓库公开与 Worker 部署分别管理，源码更新不会自动成为运行版本。

本地通过不证明：独立海外或国内网络可达、发布端离线 15 分钟后的实际读取、云端限速窗口与负载能力、账单预算、第三方自动发现或持续采用。这些按需要单独执行[公网验收](controlled-launch-plan.md)。

## 公开文件范围

源码、锁文件、Schema、合成样例和通用文档可以公开。云管理授权、发布凭据、本地数据库、原始部署日志、个人账号/付款信息和其他项目数据不纳入仓库。公开前检查纳入文件与 Git 历史；不要用 `.gitignore` 推定已提交历史已经清理。
