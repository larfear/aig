# 当前范围与后续计划

AIG 已实现独立发布者网关、文件源与可选 D1 托管链路。维护者实例的状态见[上线记录](production-launch-20261021.md)，本地复现见[开发指南](local-development.md)。契约仍为 `0.1-draft`。

## 已实现

- 公共 manifest、JSON Feed、完整资源读取。
- 独立发布者凭据、synthetic 默认模式与显式 public 模式。
- 带版本发布、幂等、冲突拒绝、更新、撤回和 D1 重启后持久读取。
- 通用发布者本地配置、单 HTTPS 目标、离线部署计划和 dry-run 构建。
- 无凭据读取验收与一键合成生命周期验收。
- Workers + D1 参考部署；公众读取与受保护写入分离。

Core 不依赖 DOS。DOS 是外部发布者适配示例，代码及其发布审核、X 发送和投递账本由发布者项目维护。

## 接下来优先解决

1. 根据实际发布者反馈改进配置、接入文档及失败恢复，继续保持同一最终正文与版本。
2. 在真实需求超过当前 Feed/资源上限时，设计明确的分页和容量策略；目前超限显式失败。
3. 根据独立客户端的网络实测记录可达性、稳定性与发布机离线后读取情况。
4. 在修改契约前说明兼容影响，使用合成用例验证新旧客户端边界。

## 按需扩展

| 能力 | 启动条件 |
| --- | --- |
| 更多内容源适配器 | 有具体网站/CMS/发布工具需要复用现有源 |
| R2 或附件 | 出现二进制对象需求；当前没有上传链路 |
| 国内托管 | 国内读取需求与实际网络测试表明有必要 |
| MCP、搜索、增量或订阅 | 有明确客户端需求与可验收的行为 |
| 更普遍的协议约定 | 多方独立接入和兼容实践足够成熟 |

当前采用海外单入口，不预建双区域同步、内容社区、自动发现网络或复杂账号系统。新增发布渠道不自动要求新增部署区域。

GitHub 源码公开与线上部署各自管理。CI 只做本地验证，不读取生产 Secret，不自动更新 Worker、开放域名或发送其他渠道内容。
