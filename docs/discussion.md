# 设计动机与取舍

发布者已经通过自己的工具或平台发布内容，希望智能体按一个明确地址直接取得同一原文、来源、版本及撤回状态。AIG 为这条交付路径提供小型参考实现。

## 为什么以网关为核心

已有线上内容源时，不应强制再提交一份正文到集中平台。AIG 通过源适配器交付资源；只有本地内容需要持续在线读取时，再启用可选托管副本。

发布者选择内容，运营方提供公网，客户端读取。AIG 只负责交付完整性和明确错误，不自动总结、评价事实或判断理解质量。

## 与已有方式的关系

AIG 复用 HTTP、JSON 与 JSON Feed，并为资源加入稳定身份、来源、连续版本、幂等及撤回约定。网站 Feed、CMS API 或静态资源可以满足许多类似需求；AIG 的价值在于为可控发布工具提供一条可直接运行、独立于社交平台的统一交付路径。

当前不宣称创造通用行业标准，也不保证智能体自动发现。是否扩大为更普遍的约定，取决于后续需求和独立接入实践。

## 首版取舍

先完成发布到完整读取、更新、撤回和必要防护。暂不实现内容社区、推荐、MCP、订阅、搜索、自动发现、多区域复制或复杂权限体系。

DOS 只是第一个发布者适配示例。其审核、X 发送、账本和内部业务结构不进入 Core。其他工具可直接遵循相同 HTTP 契约。
